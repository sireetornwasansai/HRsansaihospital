# ระบบติดตามสถานะการประเมินผลงาน (อวช.)

ระบบติดตามสถานะการประเมินผลงานเพื่อเลื่อนระดับ (อวช.) ของโรงพยาบาลสันทราย จังหวัดเชียงใหม่
ให้ผู้ยื่นตรวจสอบความคืบหน้าได้ด้วยตนเอง และให้เจ้าหน้าที่อัพเดทสถานะได้ครบทุกขั้นตอน

เว็บไซต์: https://hrsansaihospital.vercel.app/

## ภาพรวม

| ส่วน | เทคโนโลยี |
|---|---|
| หน้าเว็บ (Frontend) | ไฟล์เดียว `index.html` (HTML/CSS/JavaScript ล้วน) โฮสต์บน GitHub → Vercel |
| ระบบหลังบ้าน (Backend) | Google Apps Script (`Code.gs`) เป็น JSON API + LINE Webhook |
| ฐานข้อมูล | Google Sheets (แท็บสร้างให้อัตโนมัติ) และ Google Drive สำหรับไฟล์แนบ |
| การแจ้งเตือน | LINE Messaging API, อีเมล (MailApp) |

## ฟีเจอร์หลัก

**สำหรับผู้ยื่น**
- ยื่นเอกสาร/ติดตามสถานะด้วยเลขบัตรประชาชน แสดง flow ครบทุกขั้นตอนพร้อมจุดสถานะปัจจุบัน ระยะเวลาแต่ละขั้น และเวลารวม
- แยกเล่ม 1 / เล่ม 2 มีลายน้ำเมื่อเล่ม 1 ผ่านแล้ว และเมื่อปิดเคส
- กรอก **ชื่อผลงาน** ตอนยื่น (เจ้าหน้าที่แก้ไขได้ที่ปุ่ม “แก้ไข”) แสดงในหน้าติดตาม ตารางแอดมิน อีเมลและ LINE
- แนบไฟล์เล่ม 2 และไฟล์แก้ไขตามรอบ, หมายเหตุจากเจ้าหน้าที่
- เชื่อม LINE: "แจ้งสถานะปัจจุบัน", "ระยะเวลารวมปัจจุบัน" และรับแจ้งเตือนเมื่อสถานะเปลี่ยน ; เชื่อมได้ 2 ทาง คือกด "เชื่อมต่อ LINE" ที่เว็บเพื่อรับรหัส 6 หลัก หรือ **ทางลัด** เพิ่มเพื่อนแล้วพิมพ์เลขบัตร 13 หลักในแชท เชื่อมต่อทันที ไม่ถามเบอร์โทร (ถ้าเลขบัตรนั้นมี LINE อื่นผูกอยู่แล้ว จะให้ยืนยันเลข 4 ตัวท้ายเบอร์โทร ; ตั้ง Script Property `LINE_BIND_MODE=phone` เพื่อบังคับยืนยันเบอร์ทุกครั้ง)
- **LINE ส่งคู่มือให้อัตโนมัติ** (การ์ดปุ่ม "เปิดอ่านคู่มือ") 3 กรณี : (1) เพิ่มเพื่อนครั้งแรก (2) ผู้ใช้พิมพ์ "ช่วยเหลือ" / "คู่มือ" / help (3) บัญชีที่ยังไม่เชื่อมต่อส่งข้อความมาครบ 2 ครั้ง (ไม่ส่งซ้ำภายใน 6 ชม. เชื่อมต่อสำเร็จแล้วไม่ส่ง) ; ปรับจำนวนครั้งที่ `NOLINK_MANUAL_AT` ใน `Code.gs` ; เปลี่ยนลิงก์ด้วย Script Property `MANUAL_URL` (ค่าเริ่มต้น = `SITE_URL` + `/manual/line.html`)
- **ส่งข้อความเตือนผู้ที่เพิ่มเพื่อนแล้วแต่ยังไม่ผูก/ผูกไม่สำเร็จ** (บอกให้พิมพ์เลขบัตร 13 หลักก่อน ถ้าไม่ได้ให้ไปรับรหัส 6 หลักที่เว็บ + แนบการ์ดคู่มือ) : รัน `remindUnlinkedDryRun()` เพื่อดูจำนวนก่อน → `remindUnlinked()` เพื่อส่งจริง → `installRemindTrigger()` ให้รันเองทุกวันจันทร์ 09:00 ; ไม่ส่งถึงคนที่ผูกแล้ว/เลิกติดตาม, เตือนไม่เกิน 2 ครั้ง/คน ห่างกัน ≥ 3 วัน, ครั้งละไม่เกิน 50 คน (ปรับที่ `REMIND_*` ใน `Code.gs`) ; Push นับโควตา LINE OA
- ปุ่มสีเหลือง "อ่านคู่มือก่อน: วิธีเชื่อมต่อ LINE" แสดง 3 จุด (กรอบ QR หน้ายื่นเอกสาร, การ์ดแจ้งเตือนทาง LINE หน้าติดตามสถานะ, หน้าต่างเชื่อมต่อ LINE) เปิดคู่มือ `manual/line.html` ในแท็บใหม่
- บอร์ดคำถามที่พบบ่อย (FAQ)

**ขั้นตอนที่ระบบรองรับ** (เกณฑ์ = จำนวนวันสูงสุดต่อขั้น เกินแล้วขึ้น "ค้างนานกว่าปกติ" · แก้ได้ที่ `sla` ใน `STAGES` ของ `Code.gs`)

| กระบวนการ | ขั้นตอน (วัน) |
|---|---|
| **เล่ม 1** (ทุกระดับ) | รับเอกสาร → รพ.ตรวจสอบ (5) → แก้ไข (30) → ผอ.ลงนาม (5) → นพ.สสจ.ลงนาม (10) → ผวจ.ลงนาม (30) → ผวจ.ลงนามชี้ตัว (เริ่มนับ 180 วัน เพื่อส่งเล่ม 2) |
| **เล่ม 2 ชำนาญการ / ชำนาญงาน** | รับเอกสาร → รพ.ตรวจสอบ (5) → แก้ไข (30) → ผอ.ลงนาม (7) → สสจ.ลงรับ (3) → เข้าประชุมพิจารณา (180) → แก้ไข (30) → ส่งเอกสารแก้ไข/กรรมการอ่านซ้ำ (90) → ผ่านการประเมิน หนังสือมติ (30) |
| **เล่ม 2 ชำนาญการพิเศษ** | รับเอกสาร → รพ.ตรวจสอบ (**50**) → แก้ไข (30) → ผอ.ลงนาม (7) → นพ.สสจ.ลงนาม (15) → ผวจ.ลงนาม (30) → เขตสุขภาพที่ 1 ลงรับ (2) → เข้ารอบประชุม (90) → กรรมการอ่านผลการประเมิน (90) → แก้ไข (30) → ส่งแก้ไข/กรรมการอ่านซ้ำ (90) → มติผ่านการประเมิน (30) → หนังสือส่งกลับ |
| **คำสั่งเลื่อน** | รพ.เสนอแฟ้มคำสั่ง (5) → ผอ.ลงนาม (7) → นพ.สสจ.ลงนาม (15) → ผวจ.ลงนาม (45) → ปิดเคส |

- **ไม่มีสถานะ "รอ" แล้ว** — จุดลงนามของ ผอ. / นพ.สสจ. / ผวจ. เหลือสถานะเดียวต่อผู้ลงนาม (เช่น "ผอ.โรงพยาบาลลงนาม") พร้อมเกณฑ์วัน เมื่อลงนามเสร็จให้เลื่อนไปสถานะของหน่วยงานถัดไปทันที ; สถานะ "…ลงนามแล้ว" เดิม (`b1_dir_ok`, `b1_pho_ok`, `b2_dir_ok`, `b2_pho_ok`, `b2_gov_ok`, `cmd_dir_ok`, `cmd_pho_ok`, `cmd_gov_ok`) เลิกใช้ (`lg:true`) แต่ยังแสดงในประวัติเก่าได้
- ขั้นตอนตรวจสอบเล่ม 2 ของ รพ. แยกตามระดับ : ชำนาญการ/ชำนาญงาน = `b2_check` (5 วัน) , ชำนาญการพิเศษ = `b2_check_b` (50 วัน)
- ระบบเลือกเส้นทางเล่ม 2 จาก "ระดับตำแหน่งที่ขอเลื่อน" ตามตาราง `TRACK_TIER` ใน `Code.gs` (ปฏิบัติงาน→ชำนาญงาน และ ปฏิบัติการ→ชำนาญการ = ระดับ ก ; ที่เหลือ = ระดับ ข ; ค่าว่าง = `TIER_DEF`)
- เมื่อเล่ม 2 เสร็จ (ได้รับหนังสือแจ้งผล) เข้ากระบวนการ **ออกคำสั่งเลื่อน** แล้วปิดเคส
- ขั้นตอนเดิมที่เลิกใช้ (เช่น คุณสมบัติผ่านการประเมิน, สสจ./จังหวัดกำลังตรวจสอบ) ยังแสดงในรายการเก่าได้ แต่เลือกบันทึกใหม่ไม่ได้
- ปิดเคสได้เมื่อรายการอยู่ในขั้น "ผู้ว่าราชการจังหวัดลงนาม (คำสั่งเลื่อนระดับ)" และผู้ว่าฯ ลงนามแล้วเท่านั้น

**สำหรับเจ้าหน้าที่ (ผู้ดูแลระบบ)**
- รายการผู้ยื่น กรองตามระดับตำแหน่ง/สถานะ จัดลำดับความเร่งด่วน
- อัพเดทสถานะ พร้อมกำหนดเวลาเอง, หมายเหตุถึงผู้ยื่น (มีข้อความสำเร็จรูป), แจ้ง LINE/อีเมลอัตโนมัติ
- แก้ไขวันที่ย้อนหลังของแต่ละขั้นตอน (ตรวจลำดับเวลา และบันทึก ActivityLog)
- กรอกวันที่เป็น วัน/เดือน/ปี (พ.ศ. หรือ ค.ศ.) เวลา 24 ชั่วโมง
- **ยกเลิกรายการ** (ผู้ยื่นถอนเรื่อง / ไม่ผ่าน / เกิน 180 วัน / ย้าย-ลาออก / ซ้ำ / บันทึกผิด) — ปุ่ม “ยกเลิกรายการ” บังคับเลือกเหตุผล ปิดเคสแบบ `cancelled` จึงไม่ถูกนับเป็นงานค้าง/ค้างนาน/ใกล้ครบ 180 วันในแดชบอร์ด (ดูได้ที่การ์ด “ยกเลิกแล้ว”) และกด “กู้คืนรายการ” กลับไปขั้นตอนเดิมได้ ประวัติไม่หาย ผู้ยื่นเห็นป้ายแจ้งยกเลิกพร้อมเหตุผลในหน้าติดตาม
- **ลบรายการ** (เฉพาะผู้ดูแลระบบ) สำหรับข้อมูลผิดพลาด/แบ็กอัพผิด — ต้องระบุเหตุผล ระบบสำรองรายการ ประวัติสถานะ ไฟล์แนบ และถาม-ตอบไว้ที่แท็บ `ถังขยะ` แล้วลบทั้งหมดออก กู้คืนได้จากแท็บ “ถังขยะ” ในหน้าเจ้าหน้าที่ ; ถ้ามีประวัติ/ไฟล์แนบ/ถาม-ตอบที่ไม่มีรายการหลัก (กำพร้า) ให้รัน `cleanOrphans()` ใน Apps Script หนึ่งครั้ง
- จัดการผู้ใช้ ดูบันทึกการใช้งาน

## โครงสร้างไฟล์

```
index.html          หน้าเว็บทั้งหมด
config.js           ตั้งค่า GAS_URL (ที่อยู่ Web App) และ LINE_QR
assets/             โลโก้, favicon, line-qr.png (ไม่บังคับ)
backend/Code.gs     วางใน Google Apps Script
manual/line.html   คู่มือเชื่อมต่อ LINE สำหรับผู้ยื่น (ภาพประกอบหน้าเดียวบนเว็บ ชี้ทุกขั้นตอน 1–19 · พิมพ์ A4 แนวตั้ง 2 แผ่น) เปิดที่ /manual/line.html
manual/ch1-9.html  คู่มือเจ้าหน้าที่ (แสดงในแท็บ "คู่มือ" หน้าเจ้าหน้าที่ HR)
```

## การติดตั้ง

**Backend (Google Apps Script)**
1. สร้างโปรเจกต์ Apps Script ผูกกับ Google Sheets แล้ววาง `Code.gs` ทั้งไฟล์
2. ตั้งค่าที่ Project Settings → Script Properties

   | คีย์ | ความหมาย |
   |---|---|
   | `ADMIN_PASSWORD` | รหัสผ่านผู้ใช้ `admin` (จำเป็น) |
   | `SPREADSHEET_ID` | รหัสชีท (ไม่ใส่ = ชีทที่สคริปต์ผูกอยู่) |
   | `DRIVE_FOLDER_ID` | โฟลเดอร์เก็บไฟล์แนบ |
   | `SITE_URL` | ที่อยู่เว็บบน Vercel (ใช้ทำลิงก์ในอีเมล/LINE) |
   | `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_OA_ID`, `LINE_WEBHOOK_KEY` | ตั้งค่า LINE (ไม่บังคับ; รัน `setupLine()` เพื่อสร้าง webhook key) |
   | `HR_NOTIFY_EMAIL` | อีเมลเจ้าหน้าที่ที่ให้แจ้งเมื่อผู้ยื่นแนบไฟล์ (ไม่บังคับ) |
3. Deploy → New deployment → Web app (Execute as: Me, Access: Anyone) แล้วคัดลอก URL ที่ลงท้าย `/exec`
4. **หลังอัปเดตขั้นตอนลงนาม (รอบนี้) ให้รัน `migrateSignStages()` ใน Apps Script หนึ่งครั้ง** เพื่อย้ายรายการที่ค้างอยู่ใน "…ลงนามแล้ว" (ถ้ามี) ไปขั้นตอนถัดไป ไม่แก้ประวัติเดิม และไม่ส่ง LINE ; แท็บ `คำถามที่พบบ่อย` ที่สร้างไว้แล้วจะไม่ถูกเขียนทับ ให้แก้ข้อความ "รอลงนาม/ลงนามแล้ว" ในแท็บนั้นเอง
5. **เวลาในระบบเพี้ยน (เช่น แสดง 19:17 ทั้งที่จริง 12:17)** — เกิดจากชีทแปลงคอลัมน์เวลาเป็น "วันที่" ตามเขตเวลาของชีท รุ่นนี้บังคับคอลัมน์เวลาทุกแท็บให้เป็นข้อความและแก้ข้อมูลเก่าให้อัตโนมัติ (หรือรัน `fixTimeNow()` หนึ่งครั้ง) ; ตรวจเขตเวลาด้วย `diagTime()` และควรตั้งเขตเวลาของชีท (ไฟล์ → การตั้งค่า) เป็น Asia/Bangkok
6. **ทุกครั้งที่แก้ `Code.gs` ต้อง Deploy → Manage deployments → Edit → New version** ไม่เช่นนั้นจะขึ้น "ไม่พบคำสั่งที่เรียก"

**Frontend (GitHub → Vercel)**
1. ใส่ URL `/exec` ใน `config.js` ที่ `GAS_URL`
2. Push ขึ้น GitHub แล้วเชื่อมกับ Vercel (ไม่ต้อง build)

## ความปลอดภัยและข้อมูลส่วนบุคคล

ระบบเก็บข้อมูลบุคคล (ชื่อ ตำแหน่ง เลขบัตรประชาชน) โปรดจำกัดสิทธิ์แก้ไขชีท Drive และ Apps Script เฉพาะเจ้าหน้าที่ที่เกี่ยวข้อง
และอย่านำรหัสผ่านหรือโทเค็น LINE ขึ้น GitHub (เก็บใน Script Properties เท่านั้น)
