# ระบบติดตามสถานะการประเมินผลงาน (อวช.)

ระบบติดตามสถานะการประเมินผลงานเพื่อเลื่อนระดับ (อวช.) ของโรงพยาบาลสันทราย จังหวัดเชียงใหม่
ให้ผู้ยื่นตรวจสอบความคืบหน้าได้ด้วยตนเอง และให้เจ้าหน้าที่อัพเดทสถานะได้ครบทุกขั้นตอน

เว็บไซต์: https://hrsansaihospital.vercel.app/

## ภาพรวม

| ส่วน | เทคโนโลยี |
|---|---|
| หน้าเว็บ (Frontend) | ไฟล์เดียว `index.html` (HTML/CSS/JavaScript ล้วน) โฮสต์บน GitHub → Vercel |
| ระบบหลังบ้าน (Backend) | Google Apps Script (`Code.gs`) เป็น JSON API + LINE Webhook |
| ฐานข้อมูล | Google Sheets (แท็บสร้างให้อัตโนมัติ) และ Google Drive สำหรับไฟล์แนบ |
| การแจ้งเตือน | LINE Messaging API, อีเมล (MailApp) |

## ฟีเจอร์หลัก

**สำหรับผู้ยื่น**
- ยื่นเอกสาร/ติดตามสถานะด้วยเลขบัตรประชาชน แสดง flow ครบทุกขั้นตอนพร้อมจุดสถานะปัจจุบัน ระยะเวลาแต่ละขั้น และเวลารวม
- แยกเล่ม 1 / เล่ม 2 มีลายน้ำเมื่อเล่ม 1 ผ่านแล้ว และเมื่อปิดเคส
- กรอก **ชื่อผลงาน** ตอนยื่น (เจ้าหน้าที่แก้ไขได้ที่ปุ่ม “แก้ไข”) แสดงในหน้าติดตาม ตารางแอดมิน อีเมลและ LINE
- แนบไฟล์เล่ม 2 และไฟล์แก้ไขตามรอบ, หมายเหตุจากเจ้าหน้าที่
- เชื่อม LINE: "แจ้งสถานะปัจจุบัน", "ระยะเวลารวมปัจจุบัน" และรับแจ้งเตือนเมื่อสถานะเปลี่ยน
- บอร์ดคำถามที่พบบ่อย (FAQ)

**ขั้นตอนที่ระบบรองรับ**
- โรงพยาบาล → สำนักงานสาธารณสุขจังหวัด (สสจ.) → ศาลากลางจังหวัด (กลุ่มงานทรัพยากรบุคคล จังหวัด กำลังตรวจสอบ, มีการแก้ไข / กำลังแก้ไข หลายรอบ, ผู้ว่าราชการจังหวัดลงนาม)
- **เล่ม 2 สิ้นสุดที่** ผู้ว่าราชการจังหวัดลงนามแล้ว (ส่งกลับ รพ. เพื่อออกคำสั่งเลื่อนระดับ) แล้วเข้ากระบวนการ **ออกคำสั่งเลื่อนระดับ** 6 ขั้นตอน: ① กลุ่มงานทรัพยากรบุคคล รพ. ทำคำสั่ง → ② ผอ.โรงพยาบาลลงนาม → ③ กลุ่มงานทรัพยากรบุคคล สสจ. ตรวจสอบ → ④ นพ.สสจ. ลงนาม → ⑤ กลุ่มงานทรัพยากรบุคคล จังหวัด ตรวจสอบ → ⑥ ผู้ว่าราชการจังหวัดลงนาม → ปิดเคส
- ปิดเคสได้หลังผู้ว่าราชการจังหวัดลงนามคำสั่งเลื่อนระดับแล้วเท่านั้น

**สำหรับเจ้าหน้าที่ (ผู้ดูแลระบบ)**
- รายการผู้ยื่น กรองตามระดับตำแหน่ง/สถานะ จัดลำดับความเร่งด่วน
- อัพเดทสถานะ พร้อมกำหนดเวลาเอง, หมายเหตุถึงผู้ยื่น (มีข้อความสำเร็จรูป), แจ้ง LINE/อีเมลอัตโนมัติ
- แก้ไขวันที่ย้อนหลังของแต่ละขั้นตอน (ตรวจลำดับเวลา และบันทึก ActivityLog)
- กรอกวันที่เป็น วัน/เดือน/ปี (พ.ศ. หรือ ค.ศ.) เวลา 24 ชั่วโมง
- **ยกเลิกรายการ** (ผู้ยื่นถอนเรื่อง / ไม่ผ่าน / เกิน 180 วัน / ย้าย-ลาออก / ซ้ำ / บันทึกผิด) — ปุ่ม “ยกเลิกรายการ” บังคับเลือกเหตุผล ปิดเคสแบบ `cancelled` จึงไม่ถูกนับเป็นงานค้าง/ค้างนาน/ใกล้ครบ 180 วันในแดชบอร์ด (ดูได้ที่การ์ด “ยกเลิกแล้ว”) และกด “กู้คืนรายการ” กลับไปขั้นตอนเดิมได้ ประวัติไม่หาย ผู้ยื่นเห็นป้ายแจ้งยกเลิกพร้อมเหตุผลในหน้าติดตาม
- **ลบรายการ** (เฉพาะผู้ดูแลระบบ) สำหรับข้อมูลผิดพลาด/แบ็กอัพผิด — ต้องระบุเหตุผล ระบบสำรองรายการ ประวัติสถานะ ไฟล์แนบ และถาม-ตอบไว้ที่แท็บ `ถังขยะ` แล้วลบทั้งหมดออก กู้คืนได้จากแท็บ “ถังขยะ” ในหน้าเจ้าหน้าที่ ; ถ้ามีประวัติ/ไฟล์แนบ/ถาม-ตอบที่ไม่มีรายการหลัก (กำพร้า) ให้รัน `cleanOrphans()` ใน Apps Script หนึ่งครั้ง
- จัดการผู้ใช้ ดูบันทึกการใช้งาน

## โครงสร้างไฟล์

```
index.html          หน้าเว็บทั้งหมด
config.js           ตั้งค่า GAS_URL (ที่อยู่ Web App) และ LINE_QR
assets/             โลโก้, favicon, line-qr.png (ไม่บังคับ)
backend/Code.gs     วางใน Google Apps Script
```

## การติดตั้ง

**Backend (Google Apps Script)**
1. สร้างโปรเจกต์ Apps Script ผูกกับ Google Sheets แล้ววาง `Code.gs` ทั้งไฟล์
2. ตั้งค่าที่ Project Settings → Script Properties

   | คีย์ | ความหมาย |
   |---|---|
   | `ADMIN_PASSWORD` | รหัสผ่านผู้ใช้ `admin` (จำเป็น) |
   | `SPREADSHEET_ID` | รหัสชีท (ไม่ใส่ = ชีทที่สคริปต์ผูกอยู่) |
   | `DRIVE_FOLDER_ID` | โฟลเดอร์เก็บไฟล์แนบ |
   | `SITE_URL` | ที่อยู่เว็บบน Vercel (ใช้ทำลิงก์ในอีเมล/LINE) |
   | `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_OA_ID`, `LINE_WEBHOOK_KEY` | ตั้งค่า LINE (ไม่บังคับ; รัน `setupLine()` เพื่อสร้าง webhook key) |
   | `HR_NOTIFY_EMAIL` | อีเมลเจ้าหน้าที่ที่ให้แจ้งเมื่อผู้ยื่นแนบไฟล์ (ไม่บังคับ) |
3. Deploy → New deployment → Web app (Execute as: Me, Access: Anyone) แล้วคัดลอก URL ที่ลงท้าย `/exec`
4. **ทุกครั้งที่แก้ `Code.gs` ต้อง Deploy → Manage deployments → Edit → New version** ไม่เช่นนั้นจะขึ้น "ไม่พบคำสั่งที่เรียก"

**Frontend (GitHub → Vercel)**
1. ใส่ URL `/exec` ใน `config.js` ที่ `GAS_URL`
2. Push ขึ้น GitHub แล้วเชื่อมกับ Vercel (ไม่ต้อง build)

## ความปลอดภัยและข้อมูลส่วนบุคคล

ระบบเก็บข้อมูลบุคคล (ชื่อ ตำแหน่ง เลขบัตรประชาชน) โปรดจำกัดสิทธิ์แก้ไขชีท Drive และ Apps Script เฉพาะเจ้าหน้าที่ที่เกี่ยวข้อง
และอย่านำรหัสผ่านหรือโทเค็น LINE ขึ้น GitHub (เก็บใน Script Properties เท่านั้น)
